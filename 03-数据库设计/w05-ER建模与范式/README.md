# 第 5 周：ER 建模与范式

## Day 1-2：ER 图

### 学习内容
- 实体（矩形）、属性（椭圆）、关系（菱形）
- 关系类型：1:1, 1:N, M:N
- 如何从需求描述中识别实体

### 练习
给定需求，画出 ER 图：
```
一个班级有多个学生，一个学生可选多门课程。
每门课程有多个学生选修。课程有考试成绩。
一个老师教多门课程，一门课程只有一个老师。
```

用 dbdiagram.io 画图。

## Day 3-4：三大范式

### 学习内容
```
第一范式(1NF)：每列不可再分
  违反：address 字段存 "北京市朝阳区" → 应拆为 province, city, district

第二范式(2NF)：非主属性完全依赖主键（解决部分依赖）
  违反：(order_id, product_id) 作联合主键，但 product_name 只依赖 product_id

第三范式(3NF)：没有传递依赖
  违反：order 表里有 customer_name（customer_name 依赖 customer_id，
        customer_id 依赖 order_id，是传递依赖）
```

### 练习
拆解违反范式的表到 3NF：
```
订单表(order_id, customer_name, customer_phone,
         product_name, product_price, quantity)
```

## Day 5-7：常用设计模式

### 树形结构
| 方案 | 适用场景 | 优缺点 |
|------|---------|--------|
| 邻接表 | 层级浅（< 5 层） | 简单，递归查 |
| 闭包表 | 层级深、频繁查询子树 | 空间换时间 |
| 嵌套集 | 读多写少 | 插入删除代价大 |

### 其他模式
- **标签系统**：多对多关联表
- **软删除**：is_deleted 字段 vs 删除到单独表
- **乐观锁**：version 字段，更新时 WHERE version = ?

### 练习
对比邻接表和闭包表：
- 各插入 1 万条树形数据
- 测试查询子树的速度差异
